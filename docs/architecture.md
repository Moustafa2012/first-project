# البنية والقرارات

## ثلاثة قرارات أساسية
1. **ملف موحد لا ملفات معزولة.** `patients` ← جداول سريرية مرتبطة بـ `specialty_id` اختيارياً. الحساسية/المزمن/الأدوية بلا تخصص وتُعرض في كل قسم. مفاتيح خارجية مركّبة `(id, patient_id)` تمنع ربط سجل بمريض آخر.
2. **تاريخ لا آخر قيمة.** `observations` سلسلة زمنية (تاريخ الحدث `effective_at` ≠ `recorded_at`)، التصحيح بسجل `supersedes_id` والأصل `amended`، لا حذف (`entered_in_error` بسبب)، `audit_logs` للفروق.
3. **مشاركة = رمز + PIN + نطاق + مدة + إلغاء + سجل.** انظر `0003_sharing.sql`.

## النموذج
- سريري: `encounters, conditions, allergies, medications, procedures, imaging_studies, immunizations, family_history, appointments, care_plans, clinical_notes, test_orders, lab_reports, observations, medical_documents, specialty_records`.
- كتالوجات (يديرها المسؤول): `medical_specialties, observation_types, observation_bands, specialty_record_types`.
- وصول: `patient_members (owner|guardian|caregiver|clinician)`. حالياً يُنشأ المالك/ولي الأمر فقط؛ **دعوة مستخدم ثانٍ (مقدم رعاية/طبيب بحساب) غير منفَّذة**.
- مشاركة: `medical_shares, _items, _sessions, _access_logs, share_notes, share_attempts`.
- المعلومات الأساسية في كل مشاركة (للسلامة): هوية أساسية، الحساسية، المزمن/الخلقي، الأدوية الحالية. البنود «الحساسة» والمستندات «المقيَّدة» تُستثنى ما لم يختَرها المريض صراحة. أرقام الهوية والعنوان لا تُشارك أبداً.

## قواعد التنبيه
`observation_bands` بيانات قابلة للمراجعة (بالغون ≥ 18 فقط، بوحدة النوع الافتراضية). لا تصنيف لغير البالغين أو بعد الجهد أو دون ظرف لسكر الدم. النتيجة المخبرية تُقارن بمجالها هي، لا بجدول عام.

## ما اختُبر وما لم يُختبر
**اختُبر فعلاً:** 246 تأكيد SQL (PostgreSQL 16 حقيقي) تشمل عزل المرضى، RLS، الصلاحيات، حراس عدم التعديل، التدقيق، ومسارات المشاركة كلها (PIN خاطئ، قفل، إلغاء تلقائي، IP، انتهاء، إلغاء، نطاق، مستندات، ملاحظات) مع **اختبار طفرات** أثبت أن الاختبارات تلتقط العطل. 18 اختباراً وحدوياً. 34 خطوة Playwright على بناء إنتاج تشمل الطبيب في متصفح منفصل، المستخدم الآخر، الجوال/RTL.

**لم يُختبر:**
- **Supabase الحقيقي** (PostgREST/GoTrue/Storage): الاختبار الشامل استخدم خلفية محلية تحاكي البروتوكول. فروق دقيقة ممكنة؛ شغّل `npm run e2e` على مشروع اختباري حقيقي قبل الإنتاج.
- بريد التأكيد/استعادة كلمة المرور، وتدفق `auth/callback`.
- تكاملات خارجية (FHIR/مختبرات/أجهزة): **غير منفَّذة** ولا واجهات وهمية لها.
- فحص برمجيات خبيثة للملفات (يوجد فحص محتوى + رؤوس مشددة فقط).
- الأداء تحت حمل، النسخ الاحتياطي واستعادته، سياسة الاحتفاظ.
- الامتثال القانوني (نظام حماية البيانات الشخصية السعودي ولوائح وزارة الصحة): **لم يُراجع**. لا يُعتمد للإنتاج بلا مراجعة قانونية وطبية.
