# بوابة شفاء · Shifa Portal

سجل صحي إلكتروني متعدد المرضى. لكل مريض ملف رئيسي واحد تتفرع منه ملفات الأقسام الطبية، مع تتبع زمني للقياسات والتحاليل، ومشاركة آمنة مع الأطباء برابط + PIN.

> المنصة تنظّم المعلومات ولا تشخّص ولا تعالج. التصنيفات (مرتفع/منخفض) مؤشرات فحص عامة للبالغين تستدعي تقييم مختص، وقواعدها مخزنة كبيانات بانتظار مراجعة سريرية (`reviewed_by_clinician = false`).

## ما تقدمه

| المجال | التفاصيل |
|---|---|
| **مرضى متعددون** | ملف مستقل لكل مريض، أسرة ورعاية (ولي أمر لطفل)، رقم ملف `SH-########`، العمر محسوب من تاريخ الميلاد، كشف التكرار داخل الحساب. |
| **ملف موحد** | الحساسية والأمراض المزمنة والأدوية في الملف الرئيسي وتظهر في كل قسم **دون نسخ**. حالة الحساسية صريحة: *غير معروف / لا توجد معروفة / موثقة* (الغياب ≠ لا توجد). |
| **41 قسماً** | 33 تخصصاً سريرياً + 8 أقسام مساندة، قابلة للإضافة من لوحة المسؤول **بلا تغيير في المخطط**، ونماذج متخصصة (أسنان، عيون، سمع، ECG، إيكو، تنفس، حمل، نمو، جلد، نفسي) مخزنة كتعريفات JSON. |
| **التاريخ الطولي** | لا يُحذف شيء: «أُدخل بالخطأ» بسبب وبصمة، النتائج المعتمدة تُصحَّح بسجل جديد، سجل تدقيق append-only، تاريخ الحدث منفصل عن تاريخ التسجيل، مصدر كل معلومة ودرجة توثيقها. |
| **القياسات** | ضغط (انقباضي+انبساطي معاً) ونبض وسكر (صائم/بعد الأكل/عشوائي) ووزن وحرارة وSpO₂ وغيرها، مع الظروف والجهاز والأعراض، ورسوم 7/30/90/365/مخصص، ومقارنة بالفترة السابقة، وملخصات يومية/أسبوعية/شهرية، وCSV. |
| **التحاليل** | 90+ نوع (CBC، سكر، HbA1c، كلى، كبد، دهون، درقية، هرمونات، فيتامينات، تخثر، بول، براز، مناعة، مزارع…) بوحدتها ومجالها المرجعي **كما ورد من المختبر**، تقارير بنتائج متعددة في معاملة واحدة، ولا تُخلط الوحدات في خط واحد. |
| **المستندات** | رفع PDF/صور بفحص **المحتوى** (magic bytes) وحد 20MB ورفض PDF بمحتوى نشط، تخزين خاص، تقديم عبر الخادم برؤوس مشددة، لا روابط عامة. |
| **المشاركة** | رابط عشوائي 192 بت + PIN من 6 أرقام (bcrypt) + مدة ≤ 30 يوماً + نطاق (ملف كامل / تخصص / سجلات مختارة) + إلغاء فوري + قفل متدرج ثم إلغاء تلقائي + حد لكل IP + سجل وصول لا يحوي الأسرار. |

## الأمان (مُنفَّذ في قاعدة البيانات لا في الواجهة)

- **RLS** على كل الجداول؛ الوصول عبر `patient_members` فقط. `anon` بلا أي صلاحية. **المسؤول لا يرى بيانات المرضى.**
- لا `DELETE` على السجلات الطبية؛ `recorded_by/at` تختمها القاعدة؛ لا يمكن للمستخدم رفع «موثق من مصدر معتمد» لنفسه.
- النتيجة المعتمدة لا تُعدَّل في مكانها (مشغّل يمنع ذلك).
- دوال القارئ (`share_open/bundle/document/add_note`) متاحة لـ `service_role` فقط، والجلسة 30 دقيقة، وتُفحص الصلاحية والإلغاء والانتهاء والنطاق **عند كل طلب**.
- رقم الهوية في جدول منفصل، مُقنَّع في الواجهة، ومحجوب من التدقيق والمشاركة.
- حدود صريحة: لا يمكن منع طبيب من تصوير الشاشة؛ الطباعة والتنزيل ضوابط واجهة.

## التشغيل

```bash
npm install
cp .env.example .env.local     # عبّئ مفاتيح Supabase
# طبّق supabase/migrations/*.sql بالترتيب على مشروعك (supabase db push)
npm run dev
```

متغيرات البيئة: `NEXT_PUBLIC_SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_ANON_KEY`، `SUPABASE_SERVICE_ROLE_KEY` (خادم فقط: التخزين وبوابة الطبيب)، `NEXT_PUBLIC_SITE_URL`، `SHARE_HASH_SALT` (إلزامي في الإنتاج).

لإنشاء مسؤول: `update public.profiles set role = 'admin' where id = '<user uuid>';`

## الاختبارات

```bash
npm run typecheck && npm run lint
npm test            # 18 اختباراً وحدوياً (السلاسل الزمنية، الرسم، الأرقام، فحص الملفات)
npm run test:db     # 246 تأكيد SQL على PostgreSQL 16: العزل، RLS، الحراس، المشاركة، التدقيق
# اختبار شامل من الطرف إلى الطرف (بلا Docker):
npm run e2e:backend && npm run e2e:app && npm run e2e     # 34 خطوة Playwright
```

`scripts/dev-backend` **خلفية اختبار محلية** تترجم بروتوكول Supabase (REST/Auth/Storage) إلى SQL فعلي بدور `anon/authenticated/service_role` مع claims الـ JWT، فتكون السياسات والمشغّلات حقيقية. هي ليست PostgREST/GoTrue ولا تُستخدم في الإنتاج. انظر `docs/architecture.md` لحدود ما اختُبر.

