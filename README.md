# بوابة شفاء · Shifa Portal

[![CI](https://github.com/Moustafa2012/shifa-portal/actions/workflows/ci.yml/badge.svg)](https://github.com/Moustafa2012/shifa-portal/actions/workflows/ci.yml)

سجل صحي إلكتروني متعدد المرضى. لكل مريض ملف رئيسي واحد تتفرع منه ملفات الأقسام الطبية، مع تتبع زمني للقياسات والتحاليل، ومشاركة آمنة مع الأطباء برابط + PIN.

> المنصة تنظّم المعلومات ولا تشخّص ولا تعالج. التصنيفات (مرتفع/منخفض) مؤشرات فحص عامة للبالغين تستدعي تقييم مختص، وقواعدها مخزنة كبيانات بانتظار مراجعة سريرية (`reviewed_by_clinician = false`).

## ما تقدمه

| المجال | التفاصيل |
|---|---|
| **مرضى متعددون** | ملف مستقل لكل مريض، أسرة ورعاية (ولي أمر لطفل)، رقم ملف `SH-########`، العمر محسوب من تاريخ الميلاد، كشف التكرار داخل الحساب. |
| **ملف موحد** | الحساسية والأمراض المزمنة والأدوية في الملف الرئيسي وتظهر في كل قسم **دون نسخ**. حالة الحساسية صريحة: *غير معروف / لا توجد معروفة / موثقة* (الغياب ≠ لا توجد). |
| **41 قسماً** | 33 تخصصاً سريرياً + 8 أقسام مساندة، قابلة للإضافة من لوحة المسؤول **بلا تغيير في المخطط**، ونماذج متخصصة (أسنان، عيون، سمع، ECG، إيكو، تنفس، حمل، نمو، جلد، نفسي) مخزنة كتعريفات JSON. |
| **التاريخ الطولي** | لا يُحذف شيء: «أُدخل بالخطأ» بسبب وبصمة، النتائج المعتمدة تُصحَّح بسجل جديد، سجل تدقيق append-only، تاريخ الحدث منفصل عن تاريخ التسجيل، مصدر كل معلومة ودرجة توثيقها. |
| **القياسات** | ضغط (انقباضي+انبساطي معاً) ونبض وسكر (صائم/بعد الأكل/عشوائي) ووزن وحرارة وSpO₂ وغيرها، مع الظروف والجهاز والأعراض، ورسوم 7/30/90/365/مخصص، ومقارنة بالفترة السابقة، وملخصات يومية/أسبوعية/شهرية، وتقرير PDF متجه. |
| **التحاليل** | 140+ نوعاً (CBC كامل بمؤشراته وتفريقه، سكر، HbA1c، كلى، كبد، دهون، مؤشرات القلب، درقية، هرمونات، فيتامينات وحديد، تخثر، بول بفحصه الفيزيائي والمجهري، براز، مناعة، عدوى، مزارع…) بوحدتها ومجالها المرجعي **كما ورد من المختبر**، والوحدات المكافئة مقبولة (FT4 بـ ng/L، العدّ بـ 10^9/L…). تقارير بنتائج متعددة في معاملة واحدة، و«تحليل آخر» باسمه، ولا تُخلط الوحدات في خط واحد. |
| **قيم محسوبة** | BMI من آخر وزن وطول، وeGFR بمعادلة CKD-EPI 2021 لكل نتيجة كرياتينين، وHOMA-IR عند وجود سكر صائم وأنسولين معاً. تُحسب عند العرض ولا تُخزَّن فتتبع أي تصحيح، وتعرض المدخلات التي حُسبت منها. |
| **التواريخ الجزئية** | «حوالي 2003» أو «آذار 2003» أو تاريخ غير معروف تماماً: تُحفظ دقة التاريخ مع التاريخ (يوم / شهر / سنة / تقريبي) ولا تُعرض أبداً كيوم دقيق، في الصفحات والخط الزمني والمشاركة وPDF. |
| **منع التكرار** | تنبيه قبل حفظ سجل يبدو مكرراً (المرض نفسه، القراءة نفسها في الدقيقة نفسها، نتيجة التحليل نفسها حول التاريخ نفسه، الملف نفسه ببصمته)، مع خيار «ليس تكراراً، احفظ رغم ذلك». المقارنة تتجاهل التشكيل واختلاف رسم الهمزة والتاء المربوطة والمسافات. |
| **الفحوصات المطلوبة** | تمييز «مقترح» (من تقرير أو من المريض) عن «طلبه طبيب» مع اسم الطبيب، ويُغلق الطلب ويُربط بتقرير التحاليل الذي يجيب عنه عند حفظه. |
| **المستندات** | رفع PDF/صور بفحص **المحتوى** (magic bytes) وحد 20MB ورفض PDF بمحتوى نشط، تخزين خاص، تقديم عبر الخادم برؤوس مشددة، لا روابط عامة. |
| **المشاركة** | رابط عشوائي 192 بت + PIN من 6 أرقام (bcrypt) + مدة ≤ 30 يوماً + نطاق (ملف كامل / تخصص / سجلات مختارة) + إلغاء فوري + قفل متدرج ثم إلغاء تلقائي + حد لكل IP + سجل وصول لا يحوي الأسرار. |
| **الملف الأساسي** | ما يحتاجه كل قسم يُدخل مرة واحدة: الهوية، الطول والوزن (قراءات في القياسات وBMI محسوب)، فصيلة الدم، الحساسية، الأمراض المزمنة، الأدوية الدائمة، الأجهزة والزرعات، نمط الحياة المنظّم (التدخين بعلب-سنة، الكحول، النشاط، المهنة)، الحمل والإرضاع، مع إقرار «لا يوجد» لكل قائمة ومؤشر اكتمال. يظهر بالشكل نفسه في الملخص وكل قسم وملف الأسنان وعند الطبيب وفي PDF، مع تذكيرات خاصة بكل قسم (مثل مضادات التخثر وصمامات القلب لطبيب الأسنان) مخزنة كبيانات قابلة للمراجعة. |
| **دورة الحالة** | لكل تشخيص ودواء وحساسية زر «تغيير الحالة» يعرض الانتقالات المسموحة فقط (نشط ← شُفي، نكس، كامن، هاجع، مُستبعد؛ دواء موقوف أو منتهٍ أو مستأنف) مع التاريخ والسبب، ويُحفظ كل تغيير في سجل لا يُعدَّل. النماذج تعرف مكانها: لا يُسأل عن التخصص داخل القسم، وحقل الأسنان يظهر في ملف الأسنان فقط. |
| **التنقل** | قائمة تتبع رحلة المريض: الملخص، الملف الأساسي، الخط الزمني؛ المتابعة (القياسات، التحاليل، الفحوصات المطلوبة، خطط المتابعة)؛ الأقسام الطبية المستخدمة في الملف أولاً (الأكثر سجلات أولاً) مع «فتح قسم آخر»؛ السجلات العامة؛ المستندات والمشاركة. |
| **الإضافة في مكانها** | في مخطط الأسنان يُختار السن ثم «تشخيص لهذا السن» أو «إجراء» أو «صورة أو أشعة» دون السؤال عن السن أو التخصص. وعند الطبيب عبر الرابط: الملخص السريري أولاً، ثم التعريف والتوقيع مرة واحدة، ثم مساحة القسم (المخطط والإضافة على السن نفسه)، ونموذج الإضافة داخل كل قسم، وفي النهاية ملخص ما أضافه مع إمكان سحب أي إضافة. |
| **ملف الأسنان** | مخطط بانورامي تشريحي (تيجان، وجذور بعددها الصحيح، وقنوات، ولثة وعظم) تُرسم عليه الموجودات في أماكنها: التسوس والحشوات على أسطحها، والتاج، وحشو القناة، والآفة أو الخراج عند الذروة، والزرعة، والمفقود والمطمور، وانحسار اللثة؛ مع عرض «الأسطح» بديلاً. مخطط أسنان تفاعلي SVG بترقيم FDI (دائمة 11–48، لبنية 51–85، ومختلطة)، مرسوم من جهة الطبيب المقابل للمريض في العربية والإنجليزية، بأسطح قابلة للنقر وتحكم كامل بلوحة المفاتيح. فحوص تسجل حالة كل سن (موجود، مفقود، مخلوع، لم يبزغ، مطمور…)، وموجودات على مستوى السطح (تسوس، حشوة، تاج، علاج عصب، زرعة…) مع نوع الإثبات. المخطط الحالي مشتق من التاريخ فلا يُمسح شيء: لوحة لكل سن بتاريخه، والمخطط كما كان بعد أي فحص، ومقارنة فحصين. التشخيصات والإجراءات والأشعة تسمّي أسنانها وتظهر على المخطط (المشكلة النشطة بإطار أحمر ورمزها، وعلامة للإجراء وللصورة) وفي لوحة السن؛ والمشكلات التي لا سن لها بعد تُعرض لتحديد سنها. صفحة واحدة بتبويبات: المخطط والفحوص، المشكلات، الزيارات والإجراءات، الصور، الملف السني. ويسجل طبيب الأسنان فحصاً كاملاً عبر رابط المشاركة. |
| **إضافة الطبيب عبر الرابط** | يختار المريض ما يمكن للطبيب إضافته (زيارة، تشخيص، إجراء، ملاحظة، دواء، موعد، طلب فحص، تصوير، مستند). يعرّف الطبيب بنفسه ويوقّع على الشاشة، وتُحفظ كل إضافة باسمه داخل نطاق المشاركة، ولا يستطيع تعديل ما سجله المريض. يراجع المريض الإضافات ويبطلها فرادى أو دفعة واحدة، ويسجل التدقيق الطبيب فاعلاً. |

## الأمان (مُنفَّذ في قاعدة البيانات لا في الواجهة)

- **RLS** على كل الجداول؛ الوصول عبر `patient_members` فقط. `anon` بلا أي صلاحية. **المسؤول لا يرى بيانات المرضى.**
- لا `DELETE` على السجلات الطبية؛ `recorded_by/at` تختمها القاعدة؛ لا يمكن للمستخدم رفع «موثق من مصدر معتمد» لنفسه.
- النتيجة المعتمدة لا تُعدَّل في مكانها (مشغّل يمنع ذلك).
- دوال القارئ (`share_open/bundle/document/add_note`) متاحة لـ `service_role` فقط، والجلسة 30 دقيقة، وتُفحص الصلاحية والإلغاء والانتهاء والنطاق **عند كل طلب**.
- رقم الهوية في جدول منفصل، مُقنَّع في الواجهة، ومحجوب من التدقيق والمشاركة.
- رؤوس أمان: Content-Security-Policy للصفحات (المصادر من الموقع نفسه وخطوط Google فقط، `frame-ancestors none`، `object-src none`)، وHSTS، و`nosniff`، و`no-referrer` ومنع التخزين لروابط المشاركة.
- حدود صريحة: لا يمكن منع طبيب من تصوير الشاشة؛ الطباعة والتنزيل ضوابط واجهة.

## التشغيل

```bash
npm install
cp .env.example .env.local     # عبّئ مفاتيح Supabase
# طبّق supabase/migrations/*.sql بالترتيب على مشروعك (supabase db push)
npm run dev
```

متغيرات البيئة: `NEXT_PUBLIC_SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_ANON_KEY`، `SUPABASE_SERVICE_ROLE_KEY` (خادم فقط: التخزين وبوابة الطبيب)، `NEXT_PUBLIC_SITE_URL`، `SHARE_HASH_SALT` (إلزامي في الإنتاج)، `CRON_SECRET` (لاستدعاء `/api/cron/purge` يومياً لإتمام حذف الملفات بعد مهلة 30 يوماً).

لإنشاء مسؤول: `update public.profiles set role = 'admin' where id = '<user uuid>';`

## الاختبارات

```bash
npm run typecheck && npm run lint
npm test            # 56 اختباراً وحدوياً (السلاسل الزمنية، الرسم، القيم المحسوبة، التواريخ الجزئية، كشف التكرار، ترقيم FDI والمخطط والتشريح البانورامي، السياق السريري، دورة الحالة)
npm run test:db     # 442 تأكيد SQL على PostgreSQL 16: العزل، RLS، الحراس، المشاركة وإضافات الطبيب، التدقيق، الحذف، الكتالوج، دقة التاريخ، ملف الأسنان، الملف الأساسي، سجل الحالات، الأقسام المستخدمة
# اختبار شامل من الطرف إلى الطرف (بلا Docker):
npm run e2e:backend && npm run e2e:app && npm run e2e     # 50 خطوة Playwright
```

تُشغَّل الثلاثة تلقائياً على GitHub Actions مع كل دفع وطلب دمج (`.github/workflows/ci.yml`).

`scripts/dev-backend` **خلفية اختبار محلية** تترجم بروتوكول Supabase (REST/Auth/Storage) إلى SQL فعلي بدور `anon/authenticated/service_role` مع claims الـ JWT، فتكون السياسات والمشغّلات حقيقية. هي ليست PostgREST/GoTrue ولا تُستخدم في الإنتاج. انظر `docs/architecture.md` لحدود ما اختُبر.
